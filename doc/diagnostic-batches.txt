Improved diagnostics implementation batches (GitHub #13)
https://github.com/flamewing/asl-releases/issues/13

Audit IDs refer to diagnostic-audit.txt, based on revision 4730f629.
Preserve existing error numbers unless the meaning itself changes. For
each batch, review error-messages.md, numeric references elsewhere in the
manual, EXPECT fixtures, translations and source-position tests.

1. M68K effective-address numeric diagnostics (D01; range portion of D02).
   Implemented: computed displacement, full allowed range, operand position.
   Keep 1315/1320/1330 and warning 255/260. Details follow existing -x behavior.
   English/German catalogs updated; documentation describes these arguments.
   The evaluator accepts an optional range-check callback so the original
   integer type, unknown-symbol masking, soft ranges and relocation cleanup
   remain in the same code path. M68K uses it for address-register operands;
   PC-relative checks report the displacement after subtracting the PC base.
   Unsupported explicit extensions remain CPU errors; handled in batch 3.
   Tests: exact IDs/values/ranges/positions with one error per failure;
   boundary bytes, forward symbols, 68020 extension bytes, German detail,
   large values and soft-range warning/masking. All 339 tests pass in each
   of the embedded and external catalog configurations (GCC 16.2, Windows).

2. M68K branches, alignment and shifts (D03,D04,D09,D10,D11).
   Implemented: branch displacement/range/PC base and operand location;
   distinct instruction/operand alignment warnings; immediate count range;
   memory-shift word-size and count-1 requirements; one primary diagnostic
   after failed count/register/expression evaluation. All detail follows -x.
   Short BSR with displacement zero now uses existing error 1371 instead
   of 1370. No new error number was needed. Documentation references were
   reviewed; no existing M68K EXPECT fixture referenced this rejection.
   Other IDs and warning severity are retained. The missing documentation
   row for existing error 1391 is now included.
   Forward shift counts exposed stale ImmSymFlags use before those flags
   were populated. Use the current evaluation's flags, and defer memory
   count checks on unknown symbols. This intentionally accepts valid forward
   counts previously rejected as zero; genuinely undefined counts now report
   the symbol error. Memory counts retain their signed evaluated value for
   diagnostics rather than displaying a narrowed byte representation.
   Tests cover one diagnostic per failure, exact values/ranges/locations,
   branch PC bases +2/+4, integer/FPU/PMMU/ColdFire branches, BSR word/auto
   forms, BRA-to-NOP warning, boundary bytes, forward shifts, soft ranges,
   alignment padding/CPU differences and both catalog languages.
   Validation: all 339 tests pass in each of the embedded and external
   catalog configurations (GCC 16.2, Windows).

4. Other numeric/page/placement checks (D12,D13,D14,D15,D19).
   HC12 auto-update domain, PowerPC branch bounds and four-byte alignment,
   shared page context, 80C504 placement rule and positive array dimensions.
   Implemented with English/German detail under -x and source positions.
   IDs 1315/1320, 1375, 1900 and 1910 remain unchanged. The main text for
   1375 now describes misalignment rather than asserting an odd distance;
   PowerPC details distinguish absolute addresses from relative displacement,
   show aligned field endpoints and require multiples of four. Existing
   range/alignment check order and unknown-symbol behavior are preserved.
   HC12 reports its [-8,8] auto-update domain and stops after failed count
   evaluation. Zero still produces ordinary indexed addressing. Structures
   report that dimension zero must be at least one, retaining UInt32 checks
   and first-pass evaluation requirements.
   ChkSamePagePos accepts optional operand context; ChkSamePage remains a
   compatibility wrapper. Both addresses/page bases and the page size are
   reported without assuming caller argument order. MCS-51 callers supply
   operand positions, keeping their original current/next-PC reference.
   80C504 AJMP/ACALL identifies the instruction address and forbidden page
   offset. Automatic short/long instruction selection is unchanged.
   Numeric documentation and EXPECT references reviewed; no IDs renumbered.
   Tests cover exact IDs/details/positions, single errors, independent PPC
   field bounds/alignment, HC12 counts, page boundaries and the legacy
   wrapper, 80C504 neighbors, structures, forward symbols, translations and
   golden byte output captured from the previous build. All 340 tests pass
   with embedded and external catalogs (GCC 16.2, Windows).

5. Data-directive range reporting (D18).
   Correct overflow versus underflow, retain each directive's signed/unsigned
   combined domain, include values and limits. Review integer layouts and
   Motorola repetitions independently to preserve byte output and warnings.
   Implemented using existing ChkRangeByType at the seven integer-layout
   checks and Motorola DC/BYT/ADR checks. Report the original value versus
   the failed bound under -x, at the evaluated expression (also inside
   Motorola repetitions and Intel DUP lists). No new catalog text needed.
   Below-minimum values now use existing underflow 1315 rather than the
   former unconditional overflow 1320; above-maximum values retain 1320.
   Shared DN/DB/DW EXPECT fixtures and the commented DD underflow example
   updated, together with the numeric error documentation.
   Domains remain UInt1 for packed bits and combined signed/unsigned Int4,
   Int8, Int16, Int24, Int32, Int64 and Int128 where supported. Keep the
   existing host-width range_not_checkable exemption for widest integer
   types; do not invent bounds beyond the evaluator's representation.
   Unknown/questionable flags, masks, string/multichar conversion, float
   conversion, repetition, padding and hard-error severity are unchanged.
   Tests cover lower/upper failures, exact values/bounds/IDs/positions,
   one primary error, forward values, repeated/nested expressions, German
   diagnostics, hard ranges under -warnranges, and golden Intel/Motorola
   layouts (including 64/128-bit output and packed bitdata) captured before
   this batch. S12Z exercises the integer 24-bit DC.P form; M68K DC.P is
   decimal floating point and is not treated as an integer pointer.
   All 341 tests pass with embedded and external catalogs (GCC 16.2, Windows).

6. Function argument counts (D16,D17).
   Include function name, declaration contract and exact or minimum observed
   count. Preserve quoted commas, empty arguments and user-function semantics.
   Implemented: existing error 1490 includes function name, expected count
   or accepted interval, and supplied count, with English/German detail
   under -x at the function name. Existing numeric references/EXPECT IDs
   remain valid; the error-number table describes the new detail.
   Built-in calls whose argument parsing finishes report an exact count.
   User-function missing arguments report the consumed count. Extra user
   arguments report at least declaration-count+1; the built-in three-slot
   ceiling reports at least four. Do not evaluate or scan the unused tail
   just to claim a complete count. At that ceiling, known functions report
   their declaration; unknown names report the parser's maximum instead.
   Evaluation order, deferred unknown symbols, relocation checks, register
   argument behavior, quoted delimiters, zero-argument functions and legacy
   empty/trailing argument behavior are preserved. No new call is accepted
   or rejected. Tests cover all count branches, nested calls, variable
   built-in contracts, user functions with more than three parameters,
   source positions, single primary errors, evaluation precedence, German
   detail and golden output captured from the preceding build. All 342
   tests pass with embedded and external catalogs (GCC 16.2, Windows).

10. Remaining backend-specific delimiter diagnostics.
    Review 370, 8X30X, 9900, TMS7, NS32K, 960, KCPSM and vector operands.
    Their remaining 1300 callers include raw strings, already-split operands
    and mandatory outer delimiters. Preserve those grammars; distinguish a
    required opening delimiter from an unbalanced pair. INCLUDE's missing
    quote also uses 1300 and currently continues into a file-opening error;
    review that control flow separately from expression brackets.
    Implemented all remaining direct backend 1300 callers. Displacement
    and rotation scans in 370/8X30X/9900 now retain the source component
    and distinguish malformed delimiters from absence of displacement;
    their callers stop after the primary error. TMS7 and KCPSM also stop
    after delimiter failures. Backward scans in these paths and 960 no
    longer step before their operand buffers. NS32K reports the original
    EXT opener even though the operand split already removed it.
    Vector coordinates distinguish mandatory opening/final closing
    delimiters from mismatched closers; a trailing character after a
    balanced pair is not described as an unclosed pair. Empty coordinate
    tails cannot form a pointer before the buffer.
    INCLUDE_SearchCore returns failure for an unclosed filename quote.
    INCLUDE/BINCLUDE stop before using its uninitialized output, creating
    an input tag or opening a file. Error 1300 locates the opening quote
    and states the expected quote/end-of-filename condition. Successful
    filename search and existing delimiter/quote grammars are unchanged.
    Validation: all 346 CTest cases pass with embedded/external catalogs.
    Focused tests check IDs, positions, single errors and German detail;
    golden bytes from the preceding executable cover every affected CPU.
    Quoted/unquoted INCLUDE, filenames with spaces and BINCLUDE still
    work, and EXPECT tests confirm assembly resumes after malformed quotes.
