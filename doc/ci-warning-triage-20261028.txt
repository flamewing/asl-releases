1. Control flow and initialization: review by shared pattern
==========================================================

Start with the four GCC maybe-uninitialized locations:
- asmpars.c:2047, int_outof_range, also reported by Clang at 2025.
- asmallg.c:1387-1388, AlignValue.
- codeh8_3.c:1694, z.
- code3206x.c:642-643, dword_index.

Do not initialize every variable merely to silence the warning. In the inspected H8 decoder, z is assigned on both successful operand paths before the final if (OK). In CodeALIGN, reaching the second if (OK) requires the expression assignment in the first if (OK). In the C6x DOUBLE path, dword_index is assigned before the float conversion and only consumed after success. These examples suggest lost path correlation; confirm callees' output contracts before marking them false positives. asmpars.c needs its integer-probe/materialization and out-of-range output contracts traced separately.

Clang's larger list contains many Remainder/OK/output-parameter patterns. Review these as one helper-contract batch, then handle backend-specific cases separately. The inventory contains the full located list.

codepdk.c:1255: the default core switch branch assigns p_descr = NULL before p_descr->Id is read. Even normal branches depend on FindFamilyByName succeeding. Audit CPU registration and lookup invariants; either prove the invalid state unreachable or reject it before dereference. This is a concrete null path in the local function, not yet a demonstrated user-triggerable crash.

rescomp.c:151: malloc receives zero when no language categories are parsed. Decide whether an empty LANGS list is invalid and diagnose it, or define the empty allocation behavior. rescomp.c:195 also warns about end: the preceding scan stops only at NUL or comma, and both corresponding switch arms assign end; that warning has a local path-correlation explanation.

Validation for fixes: malformed operands and missing arguments, failed expression/conversion calls, empty resource language input, and Padauk registration/lookup invariants. Use targeted regressions for behavior changes.

2. Numeric narrowing, signedness and enum contracts
=================================================

The largest categories are implicit integer conversion, sign conversion and 64-to-32 shortening. Split by purpose:
- Backend instruction emission: verify the operand range/mask before narrowing to Byte/Word. Encode a deliberate conversion only after the proof.
- Host sizes, indexes, allocation lengths and counts: preserve size_t/oh_size_t until a checked boundary; exercise 32-bit builds.
- Enum values and flag sets: distinguish sentinel/bitmask conventions from actual out-of-domain states.
- Floating conversions: preserve the configured as_float_t precision and check integer conversion bounds.

Do not apply a repository-wide cast sweep. It can hide precisely the truncation and signedness defects this bucket should detect. The always-false comparisons at das.c:195 and codechunks.c:119 compare LargeWord lengths against SIZE_MAX: they can be redundant on one ABI but useful on a narrower size_t ABI. Retain the portability check or make the conditional intent explicit.

Validation: boundary operands, negative values, maximum address/length values, x86 and x64, and configurations with different large-integer/float widths.

3. Buffer bounds and alignment
==============================

-Wunsafe-buffer-usage dominates raw output: 116,677 observations, of which 111,664 have a parsed location, collapsing to 19,231 line/flag entries. Treat this as a separate bounds-contract audit. Start with shared string/span/dynamic-buffer primitives and then their callers; require a concrete capacity/lifetime invariant or failing input before filing a defect.

The smaller -Wcast-align family is a better immediate review target:
- p2hex.c:191-192 creates a Word* into a Byte stack array and later reads through it. Check both alignment and effective-type/aliasing requirements; explicit byte decoding or memcpy into a Word avoids relying on incidental stack alignment.
- das.c:228-229 aliases chunk byte storage as wider words. Trace allocation alignment and how the wider pointers are consumed.
- asmpars.c:3000 and related tree-to-symbol casts increase alignment requirements. Verify the tree is the embedded member of an allocated TSymbolEntry and the conversion preserves the original object address.

Also review the char-subscript warnings: cast/normalize character values before indexing where negative char values are possible. Validation should include non-ASCII bytes and alignment/undefined-behavior sanitizers where applicable.

4. Custom formatter contract
===========================

strutil.h:62-74 annotates as_snprintf/as_snprcatf/as_sdprintf/as_sdprcatf as standard printf functions via sysdefs.h's PRINTF_FORMAT_ATTR. The implementation supports extensions that standard printf checking cannot describe. This explains why invalid-specifier and extra-argument diagnostics must be triaged together with actual argument mismatches, rather than fixed by blindly editing the format strings.

Reuse the existing untracked doc/printf-format-audit.md and doc/printf-format-inventory.json as reference material; this triage did not modify them. Separate:
- Custom grammar, including large-integer formats and radix conventions.
- Real libc/chkio_fprintf type mismatches and nonliteral formats.
- Catalog/message-derived formats and wrapper annotations.

If replacing the formatter, preserve configured radix, hexadecimal case, large-integer width, byte separators, floating behavior and append/truncation semantics. If retaining it, adopt a checking strategy that understands its grammar while retaining useful checks on standard printf calls. Validation: formatter tests plus localized/catalog output and representative assembler listings.

5. Const correctness across APIs
================================

The two MSVC C4090 sites are asmpars.c:3630 and 3681. Both pass a const name into SearchSymbolHashTable, whose pName parameter at 327 is mutable and is stored in the temporary Key.Tree.Name. GCC/Clang report the same mismatch under different flags. Across nine MSVC jobs, each warning is printed again in the build summary: 36 raw lines represent two call sites.

Review the lookup key's borrowing/read-only contract, then fix the helper/data model consistently. Do not just cast away const at the two callers. Audit remaining -Wcast-qual sites separately, distinguishing borrowed read-only keys from APIs that genuinely mutate storage. Validation: global/local symbol lookup, case sensitivity and symbol table lifecycle.

6. Compiler policy, language and ABI advisories
==============================================

CMakeLists.txt:26 requires C11, while line 140 enables Clang -Weverything. Existing exclusions do not prevent -Wpre-c11-compat reports on _Noreturn, atomics and other C11 features. These are contradictions with the project's declared minimum, not reasons to remove C11 constructs.

Make explicit policy decisions for:
- Pre-C11/C99 compatibility and C++ compatibility in C-only implementation files, while preserving any real public-header C++ requirement.
- -Wpadded, -Waggregate-return and optimization/attribute suggestions: performance/ABI review, not automatic correctness fixes.
- -Wswitch-enum/-Wswitch-default/-Wcovered-switch-default: decide exhaustive switches versus deliberate sentinel/partial switches. Adding a default solely to silence a warning can hide newly added enum values.
- Float equality: distinguish sentinel/exact-format cases from approximate numerical comparisons.
- Lifetime annotation suggestions: evaluate separately from runtime lifetime defects. The dangling-global-in-main warning refers to tests/intconst_span.c assigning the local table to CurrTransTable for the duration of main; inspect teardown before treating it as a use-after-return.

Use a stable warning set for routine CI and, if useful, a separate advisory build for broader diagnostics. Do not globally suppress numeric, bounds, format or uninitialized diagnostics as part of this policy cleanup.

7. Declarations, documentation and local cleanup
===============================================

Batch documentation parameter mismatches, missing prototypes/extern declarations, reserved identifiers, extra semicolons, unused symbols and shadowing by shared header or subsystem. Correct shared headers first because one edit can remove many repeated observations.

Keep potentially behavioral warnings distinct within this bucket: fallthrough, unreachable code, comma operators, string-plus-int and duplicated branches need a quick semantic check. Mark intentional fallthrough explicitly; remove dead code only after checking configuration branches. Unused parameters in callback signatures may be intentional; missing prototypes often mean internal functions should be static.

Validation: normal build matrix after mechanical edits; focused regressions where control flow changes.

8. Endian configuration and toolchain maintenance
================================================

First: sha1.c:28 compares BYTE_ORDER and LITTLE_ENDIAN while both are undefined in the affected Clang builds. The preprocessor treats both as zero, selecting the little-endian branch and bypassing the intended unknown-endian error. This can happen to work on current little-endian runners but is a portability defect in detection. Use the project's explicit endian configuration or defined compiler endian macros and add known-answer SHA-1 tests. Check a big-endian build/emulator where available. Two macro warnings on one source line constitute one fix.

macOS: -Wpoison-system-directories repeats 1,080 times across four jobs for /usr/local/include. Trace the actual include path injection through generated compile commands, CMake modules and dependency environment; do not assume it comes from a particular workflow line. Remove the host-only path from cross/SDK-targeted compilation or make its target compatibility explicit. It is a configuration task, not 1,080 source fixes.

Pandoc: both active HTML commands in CMakeLists.txt:1129 and 1145 use --self-contained --standalone. Replace the deprecated option with --embed-resources, retaining --standalone. Fifty observations across 25 jobs reduce to two CMake call sites. Verify generated HTML embeds its resources.

Node DEP0005: one Buffer() deprecation occurs in snapshot finish-release during Download snapshot packages, using actions/download-artifact@9000827ccba6bdab643e8b6fd33ac0654aef8333. The location in the step points to the action/dependency path; it does not identify the exact package. Track an upstream action fix or collect a deprecation stack before selecting a replacement pin.
