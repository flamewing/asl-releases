# Upstream-sync optimization experiments

The starting point is experimental compatibility-fix commit `4f12da8`, based on upstream build 313. The CHARSET high-byte correction and inactive ENDM/ENDR guard are part of this baseline. The anonymous local-e benchmark copy also has its invalid expression corrected on Windows and Linux; both release and debug variants are included going forward. Identifying source details and private adaptations remain external.

Each experiment is applied separately to the latest accepted baseline, built and tested with Windows GCC, Windows MSVC and native Linux GCC, then measured with alternating baseline/candidate runs after a warmup. Timings run without concurrent builds or profiling. Generated code must match exactly between the compared binaries and remain deterministic; listing workloads also check normalized listings between baseline and candidate within each compiler. GCC/MSVC floating-point built-ins can differ in listing text even when code matches. Screen results alone do not justify committing an optimization: promising gains require an independent confirmation batch. All builds, inputs and raw results remain under D:/tmp or the native WSL benchmark directory, outside the watched checkout. Markdown paragraphs are not wrapped.

## Ordered experiments

1. Known-length line substring copies.
2. Operator discovery filtering, followed independently by a conservative simple-operand shortcut.
3. Literal spans in the new format parser.
4. Listing-local append cursor, followed independently by prefix-format preparation.
5. Expression copy/trim fusion, delayed backup copying and lazy operand initialization, each independently.

## Results

Results will be recorded here as each experiment is accepted or discarded. Percentage reductions are positive for faster builds and negative for slower builds. The compatibility fixes are already committed; this report and optimization changes will be committed with accepted experiments or the final experiment summary.

### 1. Known-length line substring copies: initially discarded; superseded by controlled retest

A caller-bounded helper replaced seven validated line/attribute extraction sites without using diagnostic position length as string length. Its independent tests covered fixed-buffer truncation and guards, dynamic growth, empty spans, and reference sources; all 319 tests passed on all three toolchains. All eleven corrected workloads produced deterministic baseline-identical code and normalized listings.

The three-pair screen and independent five-pair confirmation gave Windows GCC aggregate wall reductions of 2.26% and 3.32%, with CPU reductions of 2.52% and 2.36%; Windows MSVC gave 1.51% and 2.50% wall, and 2.07% and 2.01% CPU. Scaler v2 showed repeatable Windows wall savings of approximately 4–7%. Linux results were inconsistent across workloads. Crucially, local-e-debug slowed by 8.70% in the screen and 7.46% in a fresh seven-pair targeted repeat, slower in all three and all seven pairs respectively; the intervening confirmation showed only a 1.00% slowdown. The repeated elapsed regression initially rejected this implementation despite the Windows gains. Production changes and the candidate-specific unit test were removed. External artifacts: upstream-known-spans-20261007/{screen,confirm,stability}, builds/tests and preserved binaries.

The native local-e-debug CPU reductions were +0.14% in the screen and +0.48% in the targeted repeat: the rejection is based on elapsed time, not an established CPU regression. An identical-baseline-binary seven-pair control showed +1.36% wall reduction with mixed pairs, and all normalized listings matched between binaries. This control did not reproduce a consistent label bias; the cause of the candidate-specific elapsed-time behavior remains unestablished. No claim is made that the span helper increases CPU work.

### 2a. Operator discovery filtering: accepted

The evaluator builds a 256-bit first-byte presence map once after constant/callback handling. Absent first bytes skip full-string operator probes; present single-byte operators need no separate strchr. The quote-aware callback also rejects first-byte mismatches before strncmp. Built-in, target and callback-specific operator order, matching, precedence, quote handling and short-circuit behavior are retained. All 318 tests pass on Windows GCC, Windows MSVC and native Linux GCC. Every workload has deterministic identical code across compared binaries; normalized listings match baseline/candidate within each compiler.

| Batch | Variants | Windows GCC wall / CPU reduction | Windows MSVC wall / CPU reduction | Linux GCC wall / CPU reduction |
| --- | ---: | ---: | ---: | ---: |
| Screen, three alternating pairs | 11 | 4.29% / 3.99% | 3.25% / 2.77% | 4.76% / 4.62% |
| Independent confirmation, five alternating pairs | 5 | 4.32% / 4.08% | 2.66% / 3.31% | 4.57% / 3.94% |

These are geometric means within each batch; the two rows have different cohorts. Confirmation cases were Sonic 2, Sonic & Knuckles, ScalerMacros-v2, Madness 4 release and local-e-debug. Sonic 2 confirmed wall reductions of 5.71%/4.04%/6.09% for Windows GCC/MSVC/Linux GCC; scaler v2 confirmed 6.11%/3.31%/3.15%. Every confirmation median improved, with CPU-time averages corroborating the result. No material workload regression was observed in the full screen. The change is accepted. External artifacts: upstream-operator-filter-20261007/{screen,screen-tail,screen-combined.json,confirm}, builds/tests and preserved binaries. The Windows screen is split because the first cross-compiler listing check was too broad; baseline/candidate listings were identical within each compiler, and the corrected check compares them on that basis.

### 2b. Conservative simple-symbol shortcut: discarded

After normal constant/callback handling, this candidate bypassed discovery only for plain ASCII names when no custom target/callback operators were configured. A lazy, immutable built-in inventory check disabled the shortcut if any built-in started with a symbol character. It reused the original symbol handling, temporary-symbol logic and diagnostics. All 318 tests passed on all three toolchains; all eleven corrected workloads produced deterministic identical code and normalized listings within each compiler.

| Batch | Variants | Windows GCC wall / CPU reduction | Windows MSVC wall / CPU reduction | Linux GCC wall / CPU reduction |
| --- | ---: | ---: | ---: | ---: |
| Screen, three alternating pairs | 11 | 1.19% / 0.64% | 1.56% / 1.31% | 1.13% / 1.34% |
| Independent confirmation, five alternating pairs | 5 | 0.48% / 0.39% | 1.59% / 1.73% | -1.66% / 1.11% |

The cohorts differ: confirmation used Sonic 1, Sonic 2, Sonic Classic Heroes, ScalerMacros-v2 and local-e-debug. GCC Sonic 2 slowed by 1.71% in the Windows screen and 1.14% in confirmation; scaler v2's Windows GCC gain fell from 3.55% to 1.24%. Native elapsed times remained mixed, and native scaler v2 confirmed only 0.41% wall reduction. The modest average CPU savings and inconsistent elapsed benefit do not justify this additional shortcut and its tradeoffs. The candidate was discarded; the accepted operator filter remains the baseline. External artifacts: upstream-simple-symbol-20261007/{screen,confirm,candidate-sources,candidate.patch}, builds/tests and preserved binaries.

### 3. Literal format spans: discarded

This candidate appended runs of ordinary text outside percent specifiers in one call, preserving the new modifier parser. Independent formatter tests cover literal text, padding/alignment, precision, arbitrary-base numbers, percent escapes, fixed-buffer truncation/guards, zero and one-byte capacity, embedded NUL characters, output counts, and dynamic growth/append. All 319 tests passed on all three toolchains after correcting the test's default hexadecimal case expectation. The initial build is retained externally as a fixture-repair attempt; the measured candidate is v2.

The full eleven-variant, three-pair screen gave geometric wall/CPU reductions of -0.25%/-0.16% for Windows GCC, -0.47%/+0.76% for Windows MSVC, and +0.67%/+0.57% for Linux GCC. Windows Sonic 1 slowed by 2.99%/2.25% for GCC/MSVC. Madness 4 release improved only 0.71%/0.24% on Windows and slowed 1.85% on Linux. The expected listing-heavy benefit was not established, and the aggregate results are marginal or negative; no confirmation batch or performance commit is justified. Literal batching was removed. The independent formatter fixture is retained for subsequent formatter/listing experiments and does not change the assembler binary. External artifacts: upstream-literal-spans-v2-20261007/{screen,candidate-sources,candidate.patch}, builds/tests and preserved binaries.

### Native timing-method follow-up

The listing-cursor screen exposed substantial native I/O pressure without swap activity, memory pressure or OOM kills. In the v3 listing screen, native I/O-pressure totals increased by about 11.9 seconds while memory-pressure totals stayed zero, with elapsed changes far larger than CPU changes. Future native batches flush queued writes before each assembly, outside both elapsed and child-CPU measurement, keeping input caches intact; both binaries use this same procedure. Reports mark `sync_before_native_runs`. An identical-binary five-pair control under this procedure still showed -3.15%/-2.86% median elapsed reductions for Madness 4 debug/local-e-debug with mixed pairs, so small native wall differences cannot establish a gain on their own. Earlier uncontrolled data is retained and labelled separately; it is not directly pooled with the changed protocol. The known-span rejection depended on elapsed-only behavior and was revisited under the controlled procedure before concluding this optimization round; see the final retest below. The simple-symbol and literal-span candidates also lacked sufficiently convincing CPU gains, so their discard decisions do not depend solely on the noisy native elapsed results.

### 4a. Listing-local append cursor: discarded

The candidate tracked the physical listing-buffer length locally and appended/formatted at that offset, keeping conceptual layout widths separate. The v3 refinement removed temporary dynamic-string metadata from raw appends. All 319 tests passed on Windows GCC, Windows MSVC and Linux GCC; all eleven workloads retained deterministic identical code and normalized listings within each compiler. Additional custom-prefix checks covered includes, macro/repeat expansion, continuation lines, unknown values, repeated fields, modifiers, malformed prefixes and listing-disabled behavior. Cursor-specific formatter checks covered append counts, dynamic growth and fixed-buffer truncation.

The v3 three-pair listing-only screen gave wall/CPU reductions of 2.45%/1.48% for Windows GCC, 3.35%/2.01% for MSVC and 0.91%/1.10% for Linux. Independent five-pair confirmation over all eleven variants gave 0.51%/0.64%, 1.65%/1.01% and 0.19%/0.33%, respectively. Within the four listing-enabled cases, confirmation gave 1.94%/1.22%, 2.49%/1.70% and 0.15%/0.61%. Native confirmation used the queued-write flush procedure. The benefit is small, particularly in CPU time, and weaker on Linux; it does not justify the additional append API and buffer bookkeeping. The cursor changes were removed, retaining the general formatter fixture. External artifacts: upstream-list-cursor-v3-20261007/{screen,confirm-sync,candidate-sources,candidate.patch}, all-platform builds/tests and listing-validation logs; prior v2 results remain separately preserved.

### 4b. Listing-prefix preparation: discarded

The candidate lazily prepared prefix syntax into literal/field operations using the existing modifier parser, invalidating preparation when the command-line setting changed. Include depth, line numbers, addresses, field widths and diagnostics remained evaluated at listing time. All 319 tests passed on all three toolchains, all eleven workload outputs/listings matched, and custom-prefix/continuation/error/listing-disabled checks passed. The three-pair full-suite screen gave geometric wall/CPU reductions of 0.25%/0.14% for Windows GCC, 0.45%/1.21% for MSVC and 0.80%/0.14% for Linux. The four listing-enabled cases gave 1.14%/1.00%, 0.30%/1.21% and 1.29%/-0.54%, respectively. Linux listing CPU time did not corroborate its elapsed reduction; the small and inconsistent gains do not justify the cache and invalidation machinery. The candidate was removed. External artifacts: upstream-prefix-prep-20261007/{screen-sync,candidate-sources,candidate.patch}, builds/tests and custom-listing validation logs.

### 5a. Expression copy/trim fusion: discarded

The candidate replaced copy, leading trim and trailing trim with one bounded copy operation, retaining copy-before-trim truncation semantics and physical-string source positions. A differential fixture compared the original sequence with fusion over empty/all-whitespace, quoted/high-byte and long-growing strings, stale diagnostic lengths and fixed/dynamic capacities 1 through 32. After repairing a quoting error in the fixture, all 320 tests passed on all three toolchains and all eleven workload outputs and normalized listings matched. The three-pair screen gave geometric wall/CPU reductions of 0.41%/0.56% for Windows GCC, 0.19%/1.15% for MSVC and 0.23%/0.88% for Linux. Native local-e-debug's 5.67% elapsed slowdown was not corroborated by CPU time (+0.88% reduction), but the aggregate elapsed and CPU benefits were already too small to justify another copy helper. Fusion and its candidate-specific fixture were removed. External artifacts: upstream-copy-trim-v2-20261007/{screen-sync,candidate-sources,candidate.patch}, builds/tests and preserved binaries; the first attempt remains as an unmeasured fixture-repair build.

### 5b. Delayed expression-backup copying: discarded

This candidate moved the backup copy past immutable program-counter/integer/float handling, retaining it before string evaluation and callbacks. All 319 tests passed on all three toolchains; all eleven outputs and normalized listings matched. The three-pair screen gave geometric wall/CPU reductions of 1.28%/-0.57% for Windows GCC, 1.17%/0.73% for MSVC and 0.65%/0.67% for Linux. Scaler v1's apparent 16.54% Windows GCC elapsed gain was not corroborated by CPU time, which increased 3.23%. Native results ranged from an 8.26% CPU reduction on Sonic 1 to approximately 5% increases on Sonic 2 and Big's Fishing Derby. The full-suite CPU benefit is marginal or negative, with no consistent benefit across compilers and workloads; the candidate was removed. External artifacts: upstream-delayed-backup-20261007/{screen-sync,candidate-sources,candidate.patch}, builds/tests and preserved binaries.

### 5c. Lazy operand-result initialization: discarded

The candidate initialized the three operand results together only after discovery reached an operator or parenthesized/function path, skipping their initialization and cleanup for constants and plain symbols. Monadic slots, recursive arguments, dynamically allocated extra function arguments and existing ownership cleanup remained unchanged. All 319 tests passed on Windows GCC, MSVC and Linux GCC, including nested-function, string, float, forward-reference and error-path regression coverage; all eleven workload outputs and normalized listings matched. The three-pair screen gave geometric wall/CPU reductions of -0.03%/0.25% for Windows GCC, 0.76%/1.20% for MSVC and 0.17%/-0.60% for Linux. MSVC Madness 4 debug improved 2.88% elapsed/3.55% CPU, but Sonic 1 regressed 7.69% elapsed/5.00% CPU. Native local-e-debug's 9.40% elapsed gain did not reflect a CPU gain (CPU increased 0.72%). Overall benefit is small, mixed and insufficient to justify additional initialization state; the candidate was removed. External artifacts: upstream-lazy-operands-20261007/{screen-sync,candidate-sources,candidate.patch}, builds/tests and preserved binaries.

### 1, controlled retest. Known-length line substring copies: accepted

The seven physically bounded extraction sites and independent span tests were reapplied to accepted operator-filter HEAD `a9c38a8`, without any of the discarded expression or listing experiments. The generic defensive substring helper is unchanged; only callers that already derive bounds from the actual string use the new helper. It retains destination growth/truncation, NUL termination and source positions and never treats diagnostic Pos.Len as a physical string bound. All 320 tests passed on Windows GCC, Windows MSVC and native Linux GCC, including the retained general formatter fixture and the span-specific bounds/growth/position fixture. Every workload produced deterministic identical code and normalized baseline/candidate listings within each compiler.

| Batch | Variants | Windows GCC wall / CPU reduction | Windows MSVC wall / CPU reduction | Linux GCC wall / CPU reduction |
| --- | ---: | ---: | ---: | ---: |
| Controlled screen, three alternating pairs | 11 | 2.01% / 1.74% | 2.35% / 1.70% | -0.56% / -0.64% |
| Independent confirmation, five alternating pairs | 7 | 2.44% / 2.71% | 2.47% / 2.57% | 1.46% / 0.93% |

The cohorts differ: confirmation covered Sonic 1, Sonic 2, Sonic & Knuckles, Big's Fishing Derby, both scaler macros and local-e-debug, including every material apparent CPU regression in the screen. The screen's native scaler-v1 slowdown of 15.69% elapsed/15.68% CPU did not repeat: confirmation improved 1.13% elapsed/1.11% CPU, faster in all five pairs. Big's Fishing Derby's initial Windows GCC slowdown did not repeat; confirmation was essentially flat in wall time (-0.19%) with a 1.54% CPU reduction. MSVC Sonic 1's apparent CPU regression also disappeared. Scaler v1 confirmed Windows GCC/MSVC wall gains of 5.34%/2.41%; scaler v2 confirmed 3.96%/7.78% wall and 5.26%/8.93% CPU, faster in all five pairs on both Windows compilers. Linux scaler v2 confirmed 1.64% wall/1.65% CPU, faster in all five pairs.

Native local-e-debug confirmed a 4.25% elapsed reduction with mixed pairs and only 0.19% CPU reduction. Its elapsed result is not interpreted as a corresponding CPU saving; the earlier repeatable elapsed-only regression did not recur under the queued-write flush procedure. The decision rests on repeatable Windows wall/CPU savings and modest corroborating native CPU savings, with no repeated material workload regression. This retest supersedes the initial rejection. External artifacts: upstream-known-spans-retry-20261007/{screen-sync,confirm-sync,candidate-sources,candidate.patch}, all-platform builds/tests and preserved binaries. The older pre-filter/uncontrolled results remain separate and are not pooled with these measurements.

## Completed round

Accepted production changes are operator-discovery filtering and known-span line copying. The conservative simple-symbol shortcut, literal format spans, listing append cursor, prefix preparation, copy/trim fusion, delayed backup copying and lazy operand initialization were tested independently and removed. The general formatter fixture is retained as regression coverage; it does not change the assembler binary. The private local-e adaptation remains applied to both prepared benchmark copies, outside the repository. All measurements include the corrected local-e release/debug variants in their full-suite screens. No aggregate speedup is inferred by multiplying the independently measured percentages.
